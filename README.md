# dakoku

リポジトリごとに作業時間を記録する打刻CLI。

作業を始めるときに `dakoku in`、終わったら `dakoku out`。どのリポジトリで何をしていたかが記録に残り、あとから案件ごとの作業時間として読み出せます。複数の案件を並行して抱えていると、コミット履歴を遡っても「どれにどれだけ時間を使ったか」は分かりません。それを手元に貯めておくためのツールです。

```console
$ dakoku in "認証まわりの実装"
▶ 10:15  アクメ商事 受注管理 / 認証まわりの実装

$ dakoku out
■ 10:15 → 12:30  アクメ商事 受注管理 / 認証まわりの実装  2h15m
```

## インストール

```console
$ cargo install --git https://github.com/dachi023/dakoku
```

## 打刻する

`dakoku in` は、いまいるリポジトリで作業を開始します。カレントディレクトリから親を辿って最も近い `.git` を探すため、リポジトリのどこで打刻してもルートに紐づきます。

```console
$ dakoku in "認証まわりの実装"   # 開始
$ dakoku status                  # いま何を、何時間やっているか
$ dakoku out                     # 終了して作業時間を表示
```

### 作業を切り替える

同時に打刻できるのは1件だけです。打刻中に `dakoku in` するとエラーになります。締め忘れたまま次の作業を始めてしまうのを防ぐためです。

切り替えたいときは `--switch` を付けます。実行中のセッションを新しい開始時刻で締めてから、次を開始します。

```console
$ dakoku in "レビュー対応" --switch
■ 10:15 → 12:30  アクメ商事 受注管理 / 認証まわりの実装  2h15m
▶ 12:30  アクメ商事 受注管理 / レビュー対応
```

### 打刻し忘れたとき

`--at` で時刻を遡って指定できます。3つの形式を受け付けます。

| 形式 | 意味 |
| --- | --- |
| `--at 10:15` | 今日のその時刻。まだ未来なら前日と解釈する |
| `--at "2026-08-27 10:15"` | 日付と時刻を明示する（区切りは `T` でも可） |
| `--at -90m` | 現在から遡る。`-1h30m` や `-2h` も可 |

打刻したあとで気づいたときは `dakoku edit` で直せます。打刻中ならそのセッションを、締めたあとなら直前の記録を書き換えます。

```console
$ dakoku edit --note "認証まわりの実装とレビュー"
$ dakoku edit --in 10:15 --out 12:30
```

## 記録を見る

`dakoku log` は今日の記録を表示します。`--week`、`--month`、`--since <DATE>`、`--all` で範囲を広げ、`--here` でいまのリポジトリだけに絞れます。

```console
$ dakoku log --week
2026-08-27 (木)
  10:15 → 12:30  2h15m  アクメ商事 受注管理 / 認証まわりの実装
  14:00 → 15:10  1h10m  アクメ商事 受注管理 / 仕様のすり合わせ
  22:40 → 00:25  1h45m  アクメ商事 受注管理 / レビュー対応
                 5h10m

2026-08-28 (金)
  13:05 → 13:45  40m    dotfiles / zsh の設定整理
                 40m

dotfiles             40m
アクメ商事 受注管理  5h10m
──────────────────────────
合計                 5h50m
```

日をまたいだ作業は、開始した日の記録として1行のまま扱われます。上の `22:40 → 00:25` がそれです。

## 案件のラベルを付ける

ラベルを設定していないリポジトリは、ディレクトリ名で記録されます。上の例の `dotfiles` がそれです。案件名で集計したいリポジトリには `dakoku label` で名前を付けます。

```console
$ dakoku label set "アクメ商事 受注管理"
~/ws/src/github.com/acme/orders-api  アクメ商事 受注管理

$ dakoku label show
~/ws/src/github.com/acme/orders-api
  ラベル  アクメ商事 受注管理
```

設定済みの一覧は `dakoku label list`、解除は `dakoku label unset` です。`--path <PATH>` を付ければ、いまいる場所以外のリポジトリも操作できます。

### 設定ファイル

ラベルは `~/.dakoku/settings.json` に保存されます。手で編集する前提の形式です。

```json
{
  "projects": {
    "~/ws/src/github.com/acme": { "label": "アクメ商事" },
    "~/ws/src/github.com/acme/orders-api": { "label": "アクメ商事 受注管理" }
  }
}
```

パスは最長一致で解決します。上の例では `orders-api` は「アクメ商事 受注管理」に、`acme` 配下のそれ以外のリポジトリは「アクメ商事」になります。案件が増えるたびに個別設定を足さなくて済むよう、親ディレクトリにまとめて付けておく使い方を想定しています。

dakoku が知らないキーは書き戻すときも保持されます。独自のメモを一緒に置いても消えません。

## データの置き場所

| ファイル | 内容 |
| --- | --- |
| `~/.dakoku/settings.json` | リポジトリごとのラベル |
| `~/.dakoku/current.json` | 打刻中のセッション |
| `~/.dakoku/entries.jsonl` | 締めた記録を1行ずつ追記 |

`DAKOKU_HOME` を設定すると保存先を変えられます。

記録は1行1件の JSONL なので、dakoku を通さずに `jq` で集計することもできます。

```console
$ jq -r 'select(.label == "アクメ商事 受注管理") | .note' ~/.dakoku/entries.jsonl
```

締めた記録には、そのとき効いていたラベルを一緒に保存しています。表示のたびに設定から引き直してはいません。あとから案件名を変えても、過去の記録は請求したときのまま残ります。
